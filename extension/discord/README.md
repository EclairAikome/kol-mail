# KOL Mail Discord 私信助手

这是一个 Chrome 扩展。Discord 网页版开着的时候，它把你的私信同步到本机的 KOL Mail，再把你在 KOL Mail 里审过的回复填进 Discord 的输入框。

它不替你发消息。按回车发出去这一步永远由你自己来，扩展不按回车，不点发送按钮，也不碰你的 Discord 登录信息。Discord 会封自动发消息的账号，所以这条规矩不会变。

## 第一次安装

1. 确认这台电脑上的 KOL Mail 已经打开。
2. 在 Chrome 地址栏输入 `chrome://extensions`，按回车。
3. 打开页面右上角的“开发者模式”开关。
4. 点左上角的“加载已解压的扩展程序”，选 KOL Mail 安装文件夹里的 `extension\discord` 文件夹，也就是能看到 `manifest.json` 的那一层。默认装在 `%LOCALAPPDATA%\kol-mail\app\extension\discord`，这个路径可以直接粘贴到选择文件夹窗口顶部的地址栏里。
5. 点浏览器右上角的拼图图标，找到“KOL Mail Discord 私信助手”，点旁边的图钉，把它固定到工具栏上。
6. 点工具栏上的这个图标，会弹出设置。
7. 打开 KOL Mail，进入 设置 → 私信渠道，复制令牌，粘贴到扩展设置的“令牌”框里。端口一般保持 8765 不用动。
8. 点“保存并测试连接”。看到“已连接 KOL Mail”就装好了。
9. 已经打开着的 Discord 页面要刷新一次，扩展才会在上面出现。

## 平时怎么用

用 Chrome 打开 discord.com 放着就行。只要有一个 Discord 页面开着（放在后台标签页也算），每个私信一来新消息就会进 KOL Mail 的“私信”，不用一个个点开。

一个私信以前的聊天记录，默认要等你在 Discord 里点开它一次才会读进来。想让它不点开也读，到 KOL Mail 的 设置 → 私信渠道 里勾上“没点开过的私信，也把最近的聊天记录读进来”，下面“它读什么，不做什么”里写了这个开关具体做什么。

点进某个人的私信，右下角会出现一个小面板。面板上能看到扩展有没有连上 KOL Mail，以及这个对话有没有关联到 KOL 总表。在几个私信之间切换不用刷新页面。

还没关联时，面板会写出 KOL Mail 猜的是谁，点“去 KOL Mail 关联”，到 KOL Mail 里确认就行。

想回复时点“在 KOL Mail 里起草”，KOL Mail 会直接打开这个对话。起草、看中文回译、过合规检查都在 KOL Mail 里做。

在 KOL Mail 里批准的消息会排进面板的队列，每条写着“第 1/3 条”和中文大意。输入框是空的时候，扩展会把第一条自动填进去，你看一眼没问题就按回车。发出去以后它会等一下，再把下一条填进去。

输入框里已经有你自己打的字时，扩展不会覆盖。想换成队列里的那条，点那条下面的“填入”。某条不想发了，点“跳过”。偶尔自动填入失败，面板会给一个“复制”按钮，点了以后到输入框里粘贴。

面板太占地方的话点“收起”，它会缩成一个小标签，再点一下就展开。

## KOL Mail 更新以后

KOL Mail 自动更新时会把这个文件夹里的扩展文件一起换新，但 Chrome 不会自己重新加载扩展。更新以后到 `chrome://extensions` 找到这个扩展，点卡片右下角的刷新图标，或者直接重启 Chrome，然后把 Discord 页面也刷新一次。

如果面板上出现“KOL Mail 扩展已更新，刷新页面后继续用”，刷新 Discord 页面就好。

从 0.10 以前的版本升上来，这一步必须做一次。新版本多要了一项权限，用来知道 Discord 标签页现在停在哪个私信上，不重新加载扩展拿不到。

## 面板上的提示

| 看到的提示 | 怎么办 |
| --- | --- |
| KOL Mail 没在运行 | 打开 KOL Mail，等几秒面板会自己连上 |
| 令牌不对，到 KOL Mail 设置 → 私信渠道 复制令牌 | 重新复制令牌，点扩展图标粘贴，再点“保存并测试连接” |
| 还没填令牌 | 按上面安装步骤第 6、7 步填令牌 |
| 自动填入失败，点复制后在输入框里粘贴 | 点“复制”，在 Discord 输入框里按 Ctrl+V，检查后按回车 |
| 对方有新消息，这条草稿已作废，输入框里的字先别发 | 对方在你发之前又回了消息，KOL Mail 撤掉了这条草稿。先删掉输入框里的字，回 KOL Mail 重新起草 |
| 这是群聊私信，扩展在这里不同步，也不填入 | 群聊里有两个以上的人，扩展不碰它，在 Discord 里照常手动回 |
| 扩展内部出错，刷新页面再试 | 到 `chrome://extensions` 点这个扩展的刷新图标，再刷新 Discord 页面。0.10 以前切换私信就会出这个提示，更新后不会了 |

自动填入只在你正看着的那个 Discord 页面上发生。同一个私信开了两个页面时，只有一个会填。

## 它读什么，不做什么

它只在 discord.com 上工作，只读一对一的私信。服务器频道、群聊私信、和机器人的私信它都不读。

读的办法有两种，同时在用。

第一种是读 Discord 页面自己手里的数据。Discord 网页收到每个私信的新消息时，页面里本来就有这份数据，扩展在页面里旁听，拿到以后交给 KOL Mail。这一步不向 Discord 的服务器多要任何东西。你点开一个私信、Discord 加载出最近几十条时，扩展也是这样顺手拿到的。

第二种是读屏幕上画出来的内容，每次是当前私信里已经显示的最近 50 条。Discord 改版导致第一种办法失效时，这一种还能用，表现就和以前一样，要点开私信才读得到。

“没点开过的私信，也把最近的聊天记录读进来”这个开关在 KOL Mail 的 设置 → 私信渠道 里，默认关着。打开以后，扩展会让 Discord 页面用它自己的加载功能去取那些没点开的私信，每个私信取最近 50 条，隔五到九秒取一个，一个页面最多取 40 个。发出去的请求和你手动点开那个私信时一样，只读不发。要说明的是，Discord 的条款不允许用工具自动操作账号，这种读取被发现和处理的可能很小，但不是零，所以由你自己决定开不开。

你发的和对方发的消息都会记，图片和文件附件只记文件名和链接。沉浸式翻译插进页面的译文会先去掉，记下来的是原文。这些内容只发给本机 127.0.0.1 上的 KOL Mail，不会发到别的网站。令牌只存在扩展自己的存储里，Discord 页面读不到。

它不按回车，不点发送按钮，不发消息，不读也不保存你的 Discord 登录令牌。

## 给开发的同事

纯 JS，没有构建步骤，也不依赖 npm 包。

- `background.js` 是唯一和 KOL Mail 通信的地方，只请求 `http://127.0.0.1:<端口>/ext/discord/<操作>`，带 `X-KOL-Ext` 令牌头。它自己不向 Discord 发任何请求。清单里的 discord.com 权限只用来读标签页当前的地址：Discord 切换私信不重新加载页面，消息发送方自带的地址停在页面刚打开时的那个，0.10 以前按它判断，切到第二个私信就会被拒绝。
- `content.js` 读 Discord 页面、画面板、往输入框里填字，自己不发任何网络请求。
- `page.js` 跑在 Discord 页面自己的环境里（清单里的 `"world": "MAIN"`）。它从 webpack 的模块里找到 ChannelStore、UserStore、MessageStore 和它们的 dispatcher，订阅 `MESSAGE_CREATE`、`MESSAGE_UPDATE`、`LOAD_MESSAGES_SUCCESS`，把一对一私信的消息用 `window.postMessage` 交给 `content.js`。收到 `content.js` 的 `load` 请求时调用页面自己的 `fetchMessages`。这些都不是 Discord 的公开接口，找不到时它什么都不做。
- `popup.html` 和 `popup.js` 是设置页。
- 用 Node 20 跑 `node test/core.test.js`（读页面和判断逻辑）、`node test/page.test.js`（`page.js` 的消息整理和找模块）和 `node test/background.test.js`（对着一个假的 KOL Mail 测后台）。
- 浏览器里的检查要先在扩展目录起一个本地 http 服务，比如 `python -m http.server`。`/test/fixture.html` 照 Discord 的页面结构做了假页面，测读取和填入。`/test/app.html` 用假的扩展后台把整个流程走一遍，大约一分钟，包括先认领再填入、发出后识别、跳过、手动填入、草稿作废的提醒、中途切换私信、群聊私信和扩展失效后停下。两个页面标题显示 PASS 就算通过。
